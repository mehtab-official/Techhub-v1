# Requirements Document

## Introduction

This feature adds a secure password reset flow to the Techhub-v1 Node.js/Express backend. A registered user who has forgotten their password can request a reset link via email. The system generates a cryptographically secure token, stores its SHA-256 hash in the database with a 1-hour expiry, and emails the raw token to the user as a link. The user submits the raw token along with a new password; the system validates the token against the stored hash and expiry, updates the password, and clears the reset fields.

The implementation uses nodemailer with Gmail as the transport, adds two new fields to the User model, introduces a reusable `sendEmail` utility, and exposes two new routes on the existing auth router.

---

## Glossary

- **System**: The Techhub-v1 Express backend application.
- **User**: A registered account stored in the MongoDB `users` collection.
- **Reset_Token**: A 32-byte cryptographically random value generated by Node.js `crypto.randomBytes`, sent to the user in plain text via email.
- **Token_Hash**: The SHA-256 digest of the Reset_Token, stored in the database in place of the raw token.
- **Token_Expiry**: A UTC timestamp stored on the User document representing the moment after which the Token_Hash is no longer valid (1 hour from generation).
- **Email_Service**: The nodemailer Gmail transport configured with `GMAIL_USER` and `GMAIL_APP_PASSWORD` environment variables.
- **Forgot_Password_Handler**: The `forgotPassword` function in `authController.js`.
- **Reset_Password_Handler**: The `resetPassword` function in `authController.js`.
- **sendEmail_Utility**: The reusable mailer module at `utils/sendEmail.js`.
- **Auth_Router**: The Express router defined in `routes/authRoutes.js`.

## Requirements

### Requirement 1: User Model — Reset Token Fields

**User Story:** As a backend developer, I want the User model to store a hashed reset token and its expiry, so that the system can validate password reset requests without exposing the raw token.

#### Acceptance Criteria

1. THE System SHALL add a `resetPasswordToken` field of type `String` with no `required` constraint to the User Mongoose schema.
2. THE System SHALL add a `resetPasswordExpires` field of type `Date` with no `required` constraint to the User Mongoose schema.
3. WHEN a User document is created through the existing registration flow, THE System SHALL leave `resetPasswordToken` and `resetPasswordExpires` as `undefined` by default.

---

### Requirement 2: sendEmail Utility

**User Story:** As a backend developer, I want a reusable email-sending module, so that any controller can send transactional emails without duplicating transport configuration.

#### Acceptance Criteria

1. THE sendEmail_Utility SHALL export a single async function that accepts `{ to, subject, text }` as its argument.
2. WHEN the sendEmail_Utility function is called, THE sendEmail_Utility SHALL create a nodemailer transport using `gmail` service, authenticated with `process.env.GMAIL_USER` and `process.env.GMAIL_APP_PASSWORD`.
3. WHEN the sendEmail_Utility function is called, THE sendEmail_Utility SHALL set the `from` field to `process.env.GMAIL_USER`.
4. WHEN the email is sent successfully, THE sendEmail_Utility SHALL resolve the returned Promise without error.
5. IF the nodemailer transport fails to send the email, THEN THE sendEmail_Utility SHALL reject the returned Promise with the transport error, allowing the caller to handle it.

---

### Requirement 3: Forgot Password — Token Generation and Email Dispatch

**User Story:** As a registered user, I want to request a password reset link by providing my email address, so that I can regain access to my account when I have forgotten my password.

#### Acceptance Criteria

1. WHEN a `POST /api/auth/forgot-password` request is received with a valid `email` field in the request body, THE Forgot_Password_Handler SHALL look up the User by that email address.
2. IF no User exists for the provided email, THEN THE Forgot_Password_Handler SHALL return HTTP 404 with the message `"No account found with that email address"`.
3. WHEN a matching User is found, THE Forgot_Password_Handler SHALL generate a Reset_Token using `crypto.randomBytes(32).toString('hex')`.
4. WHEN a Reset_Token is generated, THE Forgot_Password_Handler SHALL compute the Token_Hash as the SHA-256 hex digest of the Reset_Token using Node.js `crypto.createHash('sha256')`.
5. WHEN a Token_Hash is computed, THE Forgot_Password_Handler SHALL store the Token_Hash in `user.resetPasswordToken` and set `user.resetPasswordExpires` to exactly 1 hour from the current UTC time.
6. WHEN the token fields are set, THE Forgot_Password_Handler SHALL persist the User document to the database before sending the email.
7. WHEN the User document is saved, THE Forgot_Password_Handler SHALL construct a reset URL in the format `${process.env.FRONT_URL}/reset-password/${resetToken}` and invoke the sendEmail_Utility with `to: user.email`, `subject: "Password Reset Request"`, and a `text` body containing the reset URL and a notice that the link expires in 1 hour.
8. WHEN the email is dispatched successfully, THE Forgot_Password_Handler SHALL return HTTP 200 with the message `"Password reset link sent to your email"`.
9. IF the sendEmail_Utility rejects, THEN THE Forgot_Password_Handler SHALL clear `user.resetPasswordToken` and `user.resetPasswordExpires` on the User document, persist the cleared fields to the database, and return HTTP 500 with the message `"Email could not be sent. Please try again later."`.
10. IF the request body does not contain an `email` field, THEN THE Forgot_Password_Handler SHALL return HTTP 400 with the message `"Email is required"`.

---

### Requirement 4: Reset Password — Token Validation and Password Update

**User Story:** As a registered user, I want to submit a new password using the token from my reset email, so that I can regain access to my account with a new credential.

#### Acceptance Criteria

1. WHEN a `POST /api/auth/reset-password/:token` request is received, THE Reset_Password_Handler SHALL compute the Token_Hash as the SHA-256 hex digest of the raw `:token` URL parameter.
2. WHEN the Token_Hash is computed, THE Reset_Password_Handler SHALL query the database for a User whose `resetPasswordToken` equals the Token_Hash AND whose `resetPasswordExpires` is greater than the current UTC time.
3. IF no matching User is found, THEN THE Reset_Password_Handler SHALL return HTTP 400 with the message `"Password reset token is invalid or has expired"`.
4. IF the request body does not contain a `password` field, THEN THE Reset_Password_Handler SHALL return HTTP 400 with the message `"New password is required"`.
5. WHEN a matching User is found and a `password` field is present, THE Reset_Password_Handler SHALL hash the new password using `bcrypt.hash` with a salt round of 10.
6. WHEN the new password is hashed, THE Reset_Password_Handler SHALL set `user.passwordHash` to the new hash, set `user.resetPasswordToken` to `undefined`, and set `user.resetPasswordExpires` to `undefined`.
7. WHEN the updated fields are set, THE Reset_Password_Handler SHALL persist the User document to the database.
8. WHEN the User document is saved successfully, THE Reset_Password_Handler SHALL return HTTP 200 with the message `"Password has been reset successfully"`.

---

### Requirement 5: Auth Routes — New Endpoints

**User Story:** As a frontend developer, I want two new REST endpoints for the password reset flow, so that I can integrate the forgot-password and reset-password screens into the application.

#### Acceptance Criteria

1. THE Auth_Router SHALL register a `POST /api/auth/forgot-password` route that delegates to the Forgot_Password_Handler.
2. THE Auth_Router SHALL register a `POST /api/auth/reset-password/:token` route that delegates to the Reset_Password_Handler.
3. THE System SHALL expose both routes without requiring a JWT bearer token (no `protect` middleware on these routes).

---

### Requirement 6: Environment Variables

**User Story:** As a DevOps engineer, I want the Gmail credentials stored as environment variables, so that secrets are not hard-coded in source files.

#### Acceptance Criteria

1. THE System SHALL read the Gmail sender address from `process.env.GMAIL_USER`.
2. THE System SHALL read the Gmail App Password from `process.env.GMAIL_APP_PASSWORD`.
3. THE System SHALL document both variables in the `.env` file with placeholder values so that developers know they must be configured before running the password reset feature.
